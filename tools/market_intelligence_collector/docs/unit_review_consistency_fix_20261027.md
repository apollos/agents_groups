## 实现

唯一规范 `mic/content_review_policy.py` 的金额段加入四组问题：

1. 当前材料中，什么原文支持数值所属行、期间、币种及尺度？允许跨选段引用，须理解适用范围。
2. 自己的 reason、limitation、coverage_gaps 是否仍说同一金额缺单位依据？若是，带确定单位的金额 observation 本身必须待审。
3. 哪些事实、指标、摘要或事件陈述实际依赖该金额？使用已有 `depends_on`，不能只在自由文本中提到前提。
4. 去掉待审金额后，哪些直接披露的百分比、每股单位、规格或身份信息仍能独立交付？

同时增加“金额待审、直接披露百分比独立成立、摘要依赖金额”的通用示例。
规则通过已有 `RULE_TEXT` 和 `SCHEMA_HINT` 进入抽取与仲裁提示，未增加额外模型调用或新业务审核协议。
判断仍写在原有 `status/evidence/reason/depends_on`；共享执行器继续传播状态，不解释 reason 的自然语言。

共享审核新增版本记录 `review_revision=unit_consistency_20261027`。
严格线上 URL/正文哈希复用及 clone 均检查每个合并贡献的版本，缺失或旧版本返回
`content_review_requires_refresh`。刷新仍受原调用预算限制，没有隐藏重试或额外额度。
这只是审核版本来源记录，不能证明模型语义判断正确。

历史数据库、原 claim、旧封印和历史正式查询保持原样；本次没有批量重新审核或清洗历史记录。
旧响应回放不会凭提示词更新自动变正确，已有坏记录也不能被标成已通过本轮复核。
新请求需要在既有预算内获得新模型判断；旧记录仍应按原批次报告中的限制理解。
