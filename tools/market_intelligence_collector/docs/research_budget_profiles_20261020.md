## 档位

下列上限均按单次 MIC 任务计算，失败的抓取和已发送的模型请求也计入相应次数。

| 项目 | 常规研究 / 部署上限 | 黑天鹅扫描 | `test_mode` 快速检查上限 |
|---|---:|---:|---:|
| 查询 | 4 | 2 | 2 |
| 成功取得的正文 | 4 | 2 | 2 |
| HTTP 正文尝试 | 8 | 4 | 2 |
| 浏览器正文尝试 | 4 | 2 | 2 |
| 模型调用 | 8 | 4 | 3 |
| 实际 Gateway 发送 | 8 | 4 | 3 |
| 每任务时限（秒） | 600 | 300 | 300 |

常规研究的 8 次模型调用按约 2 轮候选初筛、4 个来源抽取和少量余量设置；
初筛批次大小是 20，实际候选更多时可能超过 2 轮。
正文读取成功还可能遇到日期无法确认、重复内容或审核证据不足，不能按正文数保证有效来源数。
分块抽取、视觉转写、失败请求和仲裁也可能消耗模型或 Gateway 额度。
这些上限是需要真实证据验证的起点，不承诺额度足够完成任意研究需求。

快速检查保留初筛和正文抽取的额度。任务仍可显式请求更小的预算，例如只允许一次模型调用；
当前调用规划器会保留一次抽取额度并跳过模型初筛，所以该最小检查不能证明完整语义排序流程。

## 配置和优先级

- MIC 的 `mic/budget.py:DEFAULT_LIMITS` 与 `config/browser_runtime.yaml` 的
  `browser_runtime.limits` 保持一致；浏览器配置缺省值直接引用同一份默认值。
- Agent 的 `config/intelligence_collector.yaml` 中，`mic_task_defaults.deep_collect`
  对齐常规研究上限，`black_swan` 和 `test_mode_budget_profile` 显式使用较小预算。
- demand 的 `task_profile.mic.budget_profile` 优先于 Agent 对应任务默认值；
  `test_mode` 仅夹紧其明确配置的键，保留任务额外的限制，避免丢失较短时限或更少的 HTTP 次数。
- MIC 最终对每个已知预算项取部署上限与任务请求的较小值。
  Agent 工具超时默认也为 600 秒；外层监督器剩余时间仍可以进一步缩短任务。
- 配置目录优先级为显式 `config_dir`、`MIC_CONFIG_DIR`、仓库 `config/`。
  仓库模板变更不会自动改写用户已部署的 `~/.config/agents_groups/mic/`。
  新验收应创建新的隔离配置和证据目录，明确冻结所用预算，不能改写旧批次证据。
- 原验收批次的 30 分钟总截止仍保持固定。两项 MIC 任务各自有上限，
  还必须给行情、回读和清理留出时间；任务不能因自身尚有额度而越过批次截止。

旧 API 搜索路径的兼容缺省时限保持 7200 秒，避免浏览器默认时限调整使其被动翻倍；
显式任务时限和监督器时限仍会夹紧该值。
