## 触发问题与修复

原近期事项任务提供了商业化材料，但资本运作方向既无正式内容，也未在正式缺口中说明未覆盖；遗漏已经存在于原模型输出。另一个交付问题是 MIC 报告只提供缺口计数，Agent 因而无法直接保存具体缺口。原证据见 [摩尔线程应用验收报告](../../../agents/intelligence_collector_agent/docs/acceptance/mthreads_e2e_20261019_192205.md)。

- 同一次模型抽取按稳定的 `question_id` 对研究问题做覆盖评估，包括一句问题中的多个方向。语义判断继续由模型完成，规范与执行统一在 `content_review_policy.py` / `content_review.py`，没有公司或案例关键词规则，没有新增模型调用。
- 审核在合并与最终准入后执行。回答引用必须落到仍可发布、审核完整的核心 claim；未准入记录和 pending 事件不能证明已回答。缺失、无效或覆盖状态冲突均显式标记 `not_assessed`。缺口使用需求原文片段和固定范围说明，不把模型自由理由或“没有回答”变成公司事实。
- `report.task_coverage` 返回逐问题、逐来源审核结果；`report.coverage_gaps` 从当前 run 的正式数据库行读取完整明细，含 gap/run/source 引用。合并不再任意截断为 8 条缺口。Agent 既有持久化和正式 Reader 可保留明细，只有缺口仍不算可用结构化情报。
- 缓存中的旧问题评估保留为历史审核，本轮新问题明确记未评估。正常无产出、无模型或无有效贡献的任务也有明确缺口；取消或超时后不会为补缺口追加写入。

评估限定来源材料范围，不自动合成跨来源的“全部满足”结论。模型若错误声称已经覆盖全部方向，结构检查不能替代真实业务验收。
