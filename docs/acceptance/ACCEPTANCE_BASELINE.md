## 1. 回到项目最初的目标

原设计要建立一个供后续分析 Agent 使用的情报与数据入口：

| 组件 | 负责交付什么 | 本案例的具体责任 |
| --- | --- | --- |
| stock_data_collector | 有时间、单位、来源和质量状态的结构化市场及财务数据 | A 股日行情、最新定期报告三项财务指标及上年同期 |
| market_intelligence_collector（MIC） | 从公开材料发现、阅读、提取并保存经营、产品、行业、风险等情报 | 公司业务画像、近 90 天经营与产品变化、证据及缺口 |
| intelligence_collector_agent | 接收需求，安排两个工具，保存结果、标注质量，并向下游交付 | 完成一次真实采集流程，随后能通过正式读取入口取回资料包 |

本次问题是：**一个后续分析员拿到这些输出后，是否已经获得可信的初始研究材料？**

本次不要求情报收集员决定是否买入、预测股价、给目标价，也不要求再开发一个分析 Agent 或 Dashboard。长期研究池、盘中监控、黑天鹅、故障恢复等仍是项目功能，但不纳入本次单公司初始采集验收。

### 1.1 对此前目标漂移的纠正

此前摩尔线程方案把“MIC 从最新财报原文重新提取三项财务指标及两期数值”设成整体验收条件。这使 stock 已有的财务能力和 MIC 重复承担同一交付目标，并逐渐转向内部审核协议、报告目录遍历和大量机械断言。

本基线恢复分工：

1. 财务主交付由 stock 提供；MIC 不必再凑齐相同的六个数。
2. MIC 的主要成功标志是提取有用的经营、产品与变化信息。
3. 工具状态、事件数量、覆盖分数、断言数量，都不能替代对实际内容的验收。
4. 错单位、错金额、错主体、错期间、无依据的确定结论仍然属于真实缺陷，不能因调整分工而忽略。
5. 历史 B9 的 FAIL 结论保留。本基线用于新案例，不回写历史成绩。

## 2. 固定的实际用户需求

将以下内容作为本批任务的业务说明：

> 请为后续研究分析员收集兆易创新（603986.SH）的初始研究资料。截至本次实际运行时间，说明它的商业模式、主要存储产品及应用；取得最近 20 个已完成交易日的日行情；取得最新已披露定期报告的营业收入、归母净利润、经营活动产生的现金流量净额及上年同期数据；收集近 90 天与存储业务相关的产品、商业化或经营变化，以及需求、价格、库存、供给、客户或风险方面的公开线索。区分已证实事实、来源观点和待核实信息，保留日期、口径与来源。无法取得的信息明确列出，不编造补齐。

选择兆易创新，是因为它确实属于上市芯片设计公司，存储产品和 MCU 等非存储产品并存，能够检验系统是否理解业务边界。公司官网提供可核对的公司介绍及存储产品材料。业务画像应由 MIC 采集得到，不能把本方案的提示当作系统已经发现的事实。

本案例只采集 603986.SH 对应的 A 股行情；公司层面公开经营资料可以使用，不额外启动港股采集。

## 4. 唯一业务验收表：G1—G6

### G1 公司与产品：知道这家公司到底做什么

**通过条件**

- 正确识别兆易创新、603986.SH 与对应公司主体。
- 从 MIC 的实际采集材料解释芯片设计/Fabless 商业模式。
- 识别主要存储产品类别及至少一个有来源支持的应用方向。当前核对重点包括 NOR Flash、NAND Flash、DRAM；具体系列、细分称谓以材料为准。
- 区分存储与 MCU 等其他业务，不能把公司全部收入当作存储收入。
- 核心画像能追溯到公司官网、公司披露文件等一手材料。

**明确失败例子**

- 把公司描述成晶圆代工厂；把 MCU 当作存储芯片。
- 只有“半导体、国产替代、AI”之类标签，没有产品或业务解释。
- 内容来自预填配置或执行者常识，MIC 没有对应来源记录。

不要求客户名单、全部产品型号、每个产品收入占比齐全；材料未披露的部分说明缺口。

### G2 行情：能观察最近一段时间的交易表现

**通过条件**

- stock 覆盖截至 T 的最近 20 个交易所交易日；正常交易日交付日期、收盘价、成交量、成交额及相应单位，停牌日交付明确的停牌状态和来源。
- 本轮统一使用不复权日线，明确来源、复权口径和记录质量状态。
- 日期有序、无重复、无未来日期；缺失日能区分休市、停牌与采集缺失。
- 若有停牌，明确停牌日期及来源，不编造交易价格/成交量；不能用前值填充来伪装完整取数。
- 抽查首日、中间一日、末日，规范化记录与该工具保存的源记录/提供方结果一致。

**明确失败例子**

- 603986 的结果中混入另一家公司。
- 将盘中尚未完成的数据当最终日线，或把“手”当“股”而不换算。
- 无说明地少数日、重复日，或使用被隔离记录作为正常可用行情。
- 只报告“fetch 成功”，交付中找不到实际行情。

允许计算首末收盘价变化，注明公式与不复权口径；不要求技术指标、相对指数收益或价格预测。

### G3 财务：知道最新披露的经营规模和现金表现

**通过条件**

- 以 stock 的结构化财务结果为主要交付，取得以下三行、两期数值：

| 指标 | 本期 | 对比期 |
| --- | --- | --- |
| 营业收入 | P 对应的年初至报告期末累计值 | 上年同期累计值 |
| 归母净利润 | 同上 | 同上 |
| 经营活动产生的现金流量净额 | 同上 | 同上 |

- 六个数均能追溯至 stock 的提供方与源记录，报告期、公告日期、数值、尺度/单位及币种依据可核对。提供方明确的字段单位规范可以作为结构化数据依据。
- 主体和合并口径一致；最新三季报不能拿单季第三季度与上年全年相比。
- 报表修订和多提供方差异必须明示；不能因为两条不同口径的结果相近就宣称交叉验证成功。
- 财务信息没有因 MIC 未重复抽取而从最终资料包中消失。

**明确失败例子**

- 有更新披露的定期报告，却将更早报告无条件称为最新。
- 利润与归母净利润混用，利润代替经营现金流，或元/万元差一万倍。
- 上年同期错成上一季度。
- 实际没有某个数却用 0 填充，或仅输出同比而缺失要求的原值。

不要求六个数位于同一条记录：利润表通常提供收入与归母净利润，现金流量表提供经营现金流。核对同主体、同期间、同累计/合并口径后可以组合。

当前标准字段分别为 operating_revenue、parent_net_profit、operating_cash_flow。优先选同一主提供方、同一 report_type 的两期数据；不能用 net_profit 代理 parent_net_profit。现金流记录的 statement_type 可能因提供方不同为 cash_flow 或 cash_flow_statement，不据名称差异误判缺失。

不要求 MIC 再取得六个数，不要求计算 TTM 或估值，不要求三项同比百分比全部可计算。若上年值为负或零，保留原值和变化说明，避免给出误导性“增长率”。

### G4 近期经营情报：确实发现了公司最近的变化

**通过条件**

- MIC 在近期任务中，至少交付一条近 90 天公开披露的、与该公司存储业务直接相关的具体产品、商业化或经营进展。
- 说清“哪个产品/业务、出现什么变化、处于什么阶段、依据是什么”。事实、事件、指标均可承载，不强制必须进入某一种记录类型。
- 另外检查需求、价格、库存、供给、客户、风险这些方向：材料有答案就保留；无答案的方向明确为待核实/本轮未覆盖。无需每个方向都有结论。
- 近期来源有可核对的发布日期，并区分事件发生日期、材料发布日期、财务统计期间。
- 核心公司进展有公司披露等一手材料支持；媒体/行业观点明确归属来源，不能冒充公司已经实现的事实。

**明确失败例子**

- 只有官网长期产品目录，没有任何近期业务变化。
- 把旧新闻今天重新入库当成“近 90 天新进展”。
- 把送样、认证、规划投产写成已经批量出货。
- 只有“存储行业景气上行”，没有说明该公司实际披露了什么。
- 所有问题都返回泛化缺口，却将近期研究标成已完成。

如果限定窗口内确实找不到可核对的合格公开材料，本项为 INCONCLUSIVE，不宣称软件必然有 bug，也不降低标准改成 PASS；保留搜索和可访问性证据。

### G5 证据与自洽：材料可以被信任

**通过条件**

- G1、G3、G4 的关键陈述、数值有可定位来源；G2 有提供方及原始记录依据。
- 正式交付区分事实、推测、来源观点和缺口；同一信息在摘要、结构化记录和缺口之间不相互矛盾。
- 重要数字的正负号、尺度、期间和主体一致；未知不是 0，缺单位不是自动补“元”或 CNY。
- 被隔离/待审的信息可以作为问题展示，但不能同时作为已核实结论展示。
- 关联强度不被夸大，例如“行业 HBM 增长”不能直接变成“公司 HBM 已量产”。

**明确失败例子**

- 缺口承认金额尺度未确认，摘要却发布为确定金额。
- 引用无法支持关键结论，或是另一家公司、另一期间的材料。
- 只在最终简报隐藏错误，但错误仍在本批正式发布的关键事实/指标/事件中。

MIC 若有金额的数值和尺度依据而没有币种依据，可以保留原值、尺度并让币种为空；不得强填币种，也不必将整条有用事实丢弃。这与当前修复说明的最终版本一致。

### G6 Agent 交付：用户无需接管采集流程

**通过条件**

- 用户给定需求后，由情报收集员实际调度 stock 与 MIC，而不是执行者分别手工跑工具再冒充 Agent 结果。
- 同一批次能关联需求、任务、工具运行和正式结果。
- 采集完成后，通过 Agent 的正式读取入口获取结果；MIC 引用可通过其正式查询入口解析到对应记录与来源。
- 一个新的读取进程能复现资料内容，而不需要再次搜索、再次调用模型或再次拉行情。
- 最终资料包覆盖 G1—G4，显示 G5 的证据和限制，足以供后续分析员继续工作。

允许用简单导出脚本把正式结果排成易读表格；脚本不能补采、猜测、手填事实或调用另一个模型“完善答案”。不要求 Agent 自己输出漂亮的投资研报。

部分非核心能力失败可以保留为降级说明；不必为了资金流、估值等本次未要求的附加结果，把已经交付的核心资料全部判为无用。但必须如实保留真实任务状态，不能修改状态伪装全绿。

## 5. 判定规则与停止规则

| 判定 | 含义 |
| --- | --- |
| PASS | 对应标准满足，有可核查的实际交付 |
| FAIL | 内容错误、不自洽，或已有可访问材料/结果却未正确采集、提取、保存、交付 |
| BLOCKED | 环境、认证、依赖等前提阻止有效执行 |
| INCONCLUSIVE | 外部材料不可得、预算耗尽或证据不足，无法证明通过，也不足以判定具体实现错误 |

六项全部 PASS，才宣布：**两个工具与情报收集员已通过 MEMORY-DESIGNER-001 v1.0 单公司应用验收。**

不能扩大为“全部功能、所有公司和所有场景均已通过”。某些方向缺乏公开信息且已经明示，不自动阻断；G1—G4 的核心交付缺失则不能通过。

不以内部评分、事件条数、接口成功率、自动化断言数量代替以上判断。G1—G6 之外发现的问题记为“后续事项”，除非它已经导致上述标准失败，不得临时追加为本次阻断项。

每个 FAIL 必须给出：对应 G 编号、实际内容、相反证据、责任环节。不能只写“感觉不完整”或“还需更多测试”。

4. 用户明确改变业务目标时升级版本，说明增删的 G 项及原因；保留旧版和旧报告。
5. 某一轮失败后，复验范围应对应失败项和共享修改影响，不自动再换公司、换问题或扩大材料范围。
6. 本案例通过后，优先进入实际使用并观察。只有新的业务需求，才设计新的应用案例；不以“还可以多测一些”为由无限延长本次验收。
